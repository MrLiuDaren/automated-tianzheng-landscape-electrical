# 校核与交付

## 1. 数据校核

先查“表和表”的关系，再查“表和图”的关系。

- 所有设备、箱体、井和接驳点有唯一编号。
- 每个运行点位有类型、位置、上游和服务范围。
- 每个回路有连接负荷、需要系数、设计负荷和上游。
- 所有市集、舞台、快闪和预留负荷有归属。
- 每个服务箱覆盖的摊位不重不漏。
- 每盏灯的数量与负荷登记一致。
- 所有图中编号可在登记表定位，所有运行登记点可在图找到。
- 变更后的总数、功率和上游容量重新计算。

运行：

```powershell
python -X utf8 "<skill-dir>\scripts\validate_electrical_registers.py" `
  --load "<circuit-load-register.csv>" `
  --points "<point-register.csv>" `
  --style "<drawing-style-register.csv>"
```

脚本的警告仍需人工判断；错误必须修正后再落图或交付。

## 2. 电气技术校核

- 建筑接口的电压、相数、容量、单位和界面责任明确。
- 设计负荷的统计口径一致。
- 需要系数、同时系数、功率因数和备用比例有依据。
- 三相负荷基本平衡。
- 每个回路的保护、导体和计算电流匹配。
- 电压降满足项目标准。
- 上下游保护有选择性。
- 室外设备、插座和接线满足防护要求。
- 剩余电流保护、接地、等电位和浪涌保护按专业标准核查。
- 灯具额定电压、驱动方式和控制方式匹配。
- 舞台、快闪、市集等运营负荷没有被普通照明容量掩盖。

任何一项缺少正式参数时，在交付说明中标为“暂定”或“待专业确认”，不能写成已审定。

## 3. 空间和施工校核

- 箱体、电源点、灯具和井在绿化、铺装或构筑物上的落点可实施。
- 设备没有放入座凳内部，没有阻挡通行，没有位于易积水区。
- 草坪灯只在草坪或允许安装的区域。
- 射树灯与树位一致。
- 舞台和快闪接驳点方便拉线，但避开主要人流和舞美基础。
- 线路优先沿绿地，硬质铺装穿越有套管和保护措施。
- 线路端点在真实设备或井内，不在底图线上悬空。
- 分支、转弯、过路和检修位置有必要井。
- 与建筑、树木、水景、给排水和地下构筑物无明显冲突。
- 隐蔽设计仍保留检修和操作条件。

## 4. 图面校核

先看全图缩略图，再按区域放大：

- 图例能解释所有实际使用符号。
- 同类设备使用同一块。
- 线型、颜色、线宽在全图一致。
- 线路连续，没有意外断点和重复线。
- 主干和分支关系容易追踪。
- 设备没有被底图填充吞掉。
- 文字没有压设备、压线路、互相重叠或超出图框。
- 引线不交叉，不横穿关键设备。
- 中文没有乱码、问号或缺字。
- 总图与局部图的编号和说明一致。
- 图纸比例、图框、标题栏和设计说明与实际交付范围一致。

看图发现的问题要回到实体中修复后重新导出，不能只在截图旁加说明。

## 5. DWG 技术校核

保存前后检查：

- 当前文件路径和文件名正确。
- 修改前备份存在且可打开。
- 新增对象在预期图层和空间。
- 没有误删、误移或隐藏原有对象。
- 块比例、旋转和属性正确。
- 外部参照路径没有断裂。
- 文字样式和字体可用。
- 视口、布局和打印比例未意外改变。
- 文件保存时间与最近一次编辑一致。
- 交付副本可重新打开并读取关键实体。

建议比较修改前后的“实体总数、各图层数量、主要块数量”。数量差异应能由本轮修改解释。

## 6. 交付包

按用户要求裁剪，通常包括：

- 可编辑 DWG。
- 修改前备份。
- 点位及负荷登记表，优先提供可继续维护的 CSV 或 XLSX。
- 箱体、回路、手孔井和接驳点的编号清单。
- 必要的系统图、索引图或说明图。
- 用户要求的 JPG、PDF 或分页清单。
- 项目状态和变更记录。

文件命名应带版本或日期，避免覆盖旧交付。导出图片应包含：

- 总平面关系。
- 关键局部。
- 图例和编号说明。
- 能读清中文的最小分辨率。

## 7. 最终回答

交付时说明：

- 已完成哪些图和数据。
- 文件所在绝对路径。
- 上游容量和主要回路是否完成计算，哪些仍是暂定。
- 图面中新增了哪些对象和标注。
- 尚待建筑、运营、给排水或其他专业确认的事项。
- 下一版应从哪个文件继续。

不要把“已生成文件”写成“已通过审图”，也不要把“命令执行成功”写成“图纸已验证”。

## 8. 完成门槛

只有以下条件同时满足，才可称为本轮完成：

- 方案已覆盖当前明确需求。
- 负荷和回路数据自洽。
- 图上对象和登记表双向对应。
- 关键写入已回读。
- 总图与局部图已检查。
- 交付文件可打开并位于明确路径。
- 未决事项没有被隐藏。
